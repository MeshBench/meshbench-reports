A third of the airtime, already written and switched off

MeshCore contains the machinery to decide which node relays a flood first. It ships disabled, with a comment saying so. Turning it back on and adding one check cuts transmissions by about 30% across Scotland and Ireland, and every node still hears every message.

The finding

A repeater that hears a flood has to decide whether to rebroadcast it. MeshCore already scores each reception by signal quality and can hold a packet in proportion to that score, so the best placed node transmits first and the others learn they are not needed. The function is calcRxDelay(), it is three lines, and it works.

It returns zero. examples/simple_repeater/MyMesh.cpp sets _prefs.rx_delay_base = 0.0f; and the comment beside it reads // turn off by default, was 10.0;. The companion firmware carries the same value with a stronger note: // enable once new algo fixed. With it at zero every node in range relays the instant it receives, and the score that decides who is best placed is never consulted.

What was measured

Restoring the delay to the value the comment names, and adding one check so a node drops its own relay when it hears somebody else send the same packet, reduced transmissions from 518 to between 327 and 395 on a 308 node network. Delivery was unchanged: all 308 nodes in every run.

The two changes are separable, and neither works without the other. Suppression on its own measured exactly zero, because with the delay off there is no interval during which a node is holding a packet to suppress.

What would have made this wrong

Three faults produced confident, symmetrical, entirely false results before any of the above was true. Each was caught by a control arm that is the baseline built twice under two names, and compared against itself.

Saved state beats a compiled default

The first run of all three arms on the 308 node network returned byte identical numbers. The nodes carried prefs.json from an earlier study containing rxdelay:0, so the firmware loaded the old value and the changed default was never reached.

This generalises past this study. An A/B test on a compiled default measures nothing at all on any scenario whose nodes have run before, and it fails silently and identically in both arms, which is the worst way for a test to fail.

The build system replayed the previous arm

Go caches a test result against the package, its inputs and the environment variables the test reads. It does not track the contents of a binary that an environment variable merely points at. Rebuilding an arm and running it again returned the previous arm's numbers, which reads exactly like a change that did nothing.

The idea was implemented in the wrong queue

The first attempt cancelled the outbound queue. Flood packets are held on the inbound side, so at the moment a duplicate arrives there is nothing queued outbound and the code could not fire. The control arm made this legible in one run: exactly identical numbers, rather than a plausible small delta that would have been believed.

Limits

Two seeds, not twenty. Transmissions in the suppression arm ranged from 327 to 395, so the 30% figure is a mean of a spread rather than a stable constant. The direction was consistent and delivery never moved, which is what makes it worth reporting at this sample size.

An earlier study on this simulator established a measurement floor of about 20% with eight simultaneous senders. That floor does not apply here and it is worth saying why: it is a property of contention. A single originator flood is deterministic, and the control arm returned 518 transmissions on both seeds, to the unit. Anything with concurrent senders should still be read against the floor.

The simulator is kinder than the air: no multipath, no body loss, no oscillator error. Every result here is a best case. A saving measured in a best case is likely to be real outdoors, where collisions are more expensive rather than less.

The network is a saved import of real ScotMesh and Irish node positions, not a lattice. The same changes were also measured on a regular grid and moved in the same direction, which is some evidence the effect is not an artefact of one topology.

What this is worth

The interesting part is not the number. It is that the mechanism is already written, already in the tree, and disabled behind a comment that says it awaits a fix. Whatever is unfinished about it, the measurement suggests the thing it was written to do is worth about a third of the airtime on a real network, and that the piece it is missing is a single check performed while the packet is already being held.

That belongs with the people who wrote it.
